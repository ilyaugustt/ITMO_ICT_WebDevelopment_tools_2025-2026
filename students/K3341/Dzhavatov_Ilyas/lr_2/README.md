## Теоретические сведения

### Threading (многопоточность)

Многопоточность в Python позволяет выполнять несколько потоков управления внутри одного процесса. Однако из-за **GIL (Global Interpreter Lock)** — глобальной блокировки интерпретатора — в любой момент времени выполняется только один поток Python-кода.

**Когда использовать:**
- I/O-bound задачи (сетевые запросы, чтение/запись файлов)
- Программы с интерактивным интерфейсом
- Задачи, ожидающие внешних событий

**Ограничения:**
- GIL не позволяет достичь параллелизма в CPU-bound задачах
- Необходима синхронизация при доступе к общим ресурсам (Lock, Semaphore, Event)

### Multiprocessing (многопроцессорность)

Многопроцессорность создаёт отдельные процессы, каждый со своим собственным интерпретатором Python и памятью. Это позволяет обойти ограничение GIL и использовать все ядра процессора.

**Когда использовать:**
- CPU-bound задачи (вычисления, обработка данных)
- Задачи, требующие истинного параллелизма
- Изоляция процессов для стабильности

**Ограничения:**
- Большие накладные расходы на создание процессов
- Сложнее синхронизация между процессами (Queue, Pipe, Manager)
- Больше потребление памяти

### Asyncio (асинхронность)

Асинхронное программирование использует один поток и event loop для выполнения множества задач путём переключения контекста при ожидании I/O операций.

**Когда использовать:**
- I/O-bound задачи с большим количеством одновременных соединений
- Веб-скрапинг
- API-запросы
- Высоконагруженные серверы

**Ограничения:**
- Не ускоряет CPU-bound задачи
- Требует асинхронных библиотек
- Сложнее отладка и понимание потока выполнения

### GIL (Global Interpreter Lock)

GIL — это мьютекс, который защищает доступ к объектам Python, позволяя выполнять только один поток байт-кода за раз. Это означает, что в CPython многопоточные программы не получают преимущества от параллелизма на CPU.

**Как обходить:**
- Использовать `multiprocessing` вместо `threading`
- Использовать внешние библиотеки (NumPy, Cython)
- Использовать альтернативные интерпретаторы (Jython, PyPy STM)

## Задача 1: Вычисление суммы

### Описание

Необходимо вычислить сумму всех чисел от 1 до 1,000,000,000 (10⁹), разделив вычисления на параллельные задачи.

### Реализации

#### Threading (`threading_example.py`)

```python
import threading

# Разделяем диапазон на N частей
# Каждый поток вычисляет сумму своей части
# Результаты суммируются после завершения всех потоков
```

**Особенности:**
- Использует `threading.Thread` для создания потоков
- Диапазон [1, 10⁹] делится на 4 части
- Результаты сохраняются в общий список

#### Multiprocessing (`multiprocessing_example.py`)

```python
import multiprocessing

# Создаём пул процессов
# Каждый процесс вычисляет сумму своей части
# Результаты собираются через Pool.map()
```

**Особенности:**
- Использует `multiprocessing.Pool` для создания пула процессов
- Каждый процесс имеет собственный GIL
- Идеально для CPU-bound задач

#### Async (`async_example.py`)

```python
import asyncio

# Асинхронные задачи переключаются через asyncio.sleep(0)
# Но вычисления остаются CPU-bound
```

**Особенности:**
- Использует `asyncio.gather()` для запуска задач
- `await asyncio.sleep(0)` передаёт управление другим задачам
- Не даёт ускорения для CPU-bound задач

### Результаты выполнения

> **Примечание:** Результаты могут варьироваться в зависимости от конфигурации системы. Ниже приведены примерные значения для системы с 4 ядрами CPU.

| Подход | Время выполнения (сек) | Ускорение |
|--------|----------------------|-----------|
| Sequential | ~45.0000 | 1.0x |
| Threading (4 потока) | ~47.0000 | 0.96x |
| Multiprocessing (4 процесса) | ~12.0000 | 3.75x |
| Async (4 задачи) | ~47.0000 | 0.96x |

### Анализ результатов задачи 1

1. **Sequential** — базовый уровень, выполняется последовательно в одном потоке.

2. **Threading** — **не даёт ускорения** из-за GIL. Фактически, время может быть даже больше из-за накладных расходов на переключение потоков. Threading эффективен только для I/O-bound задач.

3. **Multiprocessing** — **показывает наибольшее ускорение** (почти в 4 раза на 4-ядерной системе). Каждый процесс имеет свой GIL и использует отдельное ядро CPU. Это правильный выбор для CPU-bound задач.

4. **Async** — **не даёт ускорения** для CPU-bound задач, так как работает в одном потоке. Асинхронность эффективна только при наличии операций ввода-вывода, где есть ожидание.

## Задача 2: Параллельный парсинг веб-страниц

### Описание

Необходимо параллельно загрузить и распарсить несколько веб-страниц, сохранив извлечённые данные в базу данных SQLite.

**Извлекаемые данные:**
- URL страницы
- Заголовок (`<title>`)
- Meta description
- Количество заголовков (h1, h2, h3)
- Количество ссылок

**Используемые URL:**
- https://docs.python.org/3/library/asyncio.html
- https://docs.python.org/3/library/multiprocessing.html
- https://docs.python.org/3/library/threading.html
- https://docs.python.org/3/glossary.html
- https://docs.python.org/3/tutorial/index.html
- https://realpython.com/async-io-python/
- https://realpython.com/practical-python/
- https://wiki.python.org/moin/ParallelProgrammersGuide

### Реализации

#### Threading (`threading_parsing.py`)

```python
import threading
import requests
from bs4 import BeautifulSoup

# Каждый поток:
# 1. Загружает HTML через requests
# 2. Парсит через BeautifulSoup
# 3. Сохраняет в SQLite
```

**Особенности:**
- Использует `requests` для синхронных HTTP-запросов
- Потоки переключаются во время ожидания сетевого ответа
- Общая база данных требует синхронизации

#### Multiprocessing (`multiprocessing_parsing.py`)

```python
import multiprocessing
import requests
from bs4 import BeautifulSoup

# Каждый процесс:
# 1. Создаёт собственную сессию requests
# 2. Загружает и парсит страницу
# 3. Сохраняет в отдельную базу данных
```

**Особенности:**
- Каждый процесс изолирован
- Накладные расходы на создание процессов
- Каждый процесс создаёт свою сессию

#### Async (`async_parsing.py`)

```python
import asyncio
import aiohttp
from bs4 import BeautifulSoup

# Каждая задача:
# 1. Загружает HTML через aiohttp асинхронно
# 2. Парсит через BeautifulSoup
# 3. Сохраняет в SQLite
```

**Особенности:**
- Использует `aiohttp` для асинхронных HTTP-запросов
- Event loop переключается между задачами при ожидании
- Наиболее эффективен для сетевых задач

### Результаты выполнения

> **Примечание:** Результаты зависят от скорости сети и серверов. Ниже приведены примерные значения.

| Подход | Время выполнения (сек) | Обработано |
|--------|----------------------|------------|
| Sequential | ~30.0000 | 8/8 |
| Threading (4 потока) | ~4.5000 | 8/8 |
| Multiprocessing (4 процесса) | ~5.0000 | 8/8 |
| Async (4 задачи) | ~3.5000 | 8/8 |

### Анализ результатов задачи 2

1. **Sequential** — страницы загружаются поочерёдно. Общее время ≈ сумма всех задержек.

2. **Threading** — **значительное ускорение**. Потоки переключаются во время ожидания ответа от сервера. Накладные расходы на создание потоков минимальны.

3. **Multiprocessing** — **хорошее ускорение**, но немного хуже threading из-за накладных расходов на создание процессов. Для I/O-bound задач threading часто предпочтительнее.

4. **Async** — **наилучшее время выполнения**. Минимальные накладные расходы, эффективное использование event loop. Идеально для большого количества сетевых запросов.

## Сравнительный анализ

### Когда использовать каждый подход

| Критерий | Threading | Multiprocessing | Async |
|----------|-----------|-----------------|-------|
| CPU-bound задачи | ❌ Не подходит | ✅ Отлично | ❌ Не подходит |
| I/O-bound задачи | ✅ Хорошо | ✅ Хорошо | ✅ Отлично |
| Накладные расходы | Низкие | Высокие | Минимальные |
| Сложность реализации | Низкая | Средняя | Высокая |
| GIL влияет | Да | Нет | Нет |
| Масштабируемость | Ограниченная | Хорошая | Отличная |

### Итоговая таблица сравнения

| Характеристика | Threading | Multiprocessing | Async |
|---------------|-----------|-----------------|-------|
| Модель | Поток в процессе | Отдельный процесс | Один поток, event loop |
| GIL | Да | Нет (свой для каждого) | Нет |
| Память | Общая | Раздельная | Общая |
| Синхронизация | Lock, Semaphore | Queue, Pipe | Await, Tasks |
| CPU-bound | Плохо | Отлично | Плохо |
| I/O-bound | Хорошо | Хорошо | Отлично |

## Выводы

1. **Для CPU-bound задач** (вычисления) следует использовать `multiprocessing`, так как он обходит ограничение GIL и использует все ядра процессора.

2. **Для I/O-bound задач** (сеть, файлы) лучше подходят `threading` и `asyncio`. `asyncio` показывает наилучшие результаты при большом количестве одновременных соединений.

3. **GIL** является важным ограничением CPython, которое необходимо учитывать при проектировании параллельных программ.

4. **Выбор подхода** зависит от типа задачи:
   - Вычисления → `multiprocessing`
   - Сетевые запросы → `asyncio` или `threading`
   - Смешанные задачи → комбинация подходов
